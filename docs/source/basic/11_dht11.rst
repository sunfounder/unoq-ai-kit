11 Temperature & Humidity Monitor
=================================

So far you've worked with simple sensors — buttons, tilt switches, photoresistors, and ultrasonic modules. Now you'll use your first **digital sensor module**: the DHT11, which measures both **temperature** and **humidity** and communicates readings digitally over a single data pin. The sensor does the hard work of converting physical conditions into numbers — you just call a function and get the answer. This is also your first lesson using an **external library** to talk to a sensor.

In this lesson, you will learn to:

* Install and use the **DHT sensor library** in App Lab
* Read temperature (Celsius) and humidity (%) from the DHT11
* Use ``millis()`` for **non-blocking timing** — checking the clock without freezing your program
* Handle sensor errors gracefully with ``isnan()``

**The Sketch (sketch.ino)**

Now that you've seen live climate data streaming in, let's look at the sketch file.

.. code-block:: cpp
   :linenos:

   /*
    * Reads temperature and humidity from DHT11 every 2 seconds.
    */

   #include "DHT.h"

   #define DHTPIN 2        // DHT11 data pin connected to pin 2
   #define DHTTYPE DHT11   // DHT11 sensor type

   DHT dht(DHTPIN, DHTTYPE);

   unsigned long lastReadTime = 0;
   const unsigned long interval = 2000;  // Read every 2 seconds

   void setup() {
       Serial.begin(115200);  // Start Serial Monitor at 115200 baud
       dht.begin();            // Initialize DHT11 sensor

       Serial.println("=== DHT11 Temperature & Humidity ===");
   }

   void loop() {
       unsigned long currentMillis = millis();

       // Check if it's time for a new reading (non-blocking)
       if (currentMillis - lastReadTime >= interval) {
           lastReadTime = currentMillis;

           float humidity = dht.readHumidity();
           float temperature = dht.readTemperature();  // Celsius

           // Check if readings are valid
           if (isnan(humidity) || isnan(temperature)) {
               Serial.println("Failed to read from DHT11!");
               return;
           }

           Serial.print("Temperature: ");
           Serial.print(temperature);
           Serial.print(" *C   ");

           Serial.print("Humidity: ");
           Serial.print(humidity);
           Serial.println(" %");
       }
   }

**How it Works**

This lesson introduces the ``millis()`` non-blocking timer — one of the most important patterns in Arduino programming. Instead of freezing your entire program with ``delay()``, you check the clock and act only when it's time:

.. code-block:: text

   setup() → runs once at startup:
       Start Serial Monitor at 115200 baud
       Initialize DHT11 sensor
       Print startup message

   loop() → runs over and over forever:
       Check current time with millis()
       Has 2 seconds passed since the last reading?
           YES → update lastReadTime to now
               Read temperature and humidity from DHT11
               Are the values valid?
                   YES → print temperature (°C) and humidity (%)
                   NO  → print error message
               (loop continues — does other checks if needed)
           NO  → nothing to do, loop runs again immediately

#. **Library Include, Macros, and DHT Object**

   - The ``DHT.h`` library provides the ``DHT`` class, handling the DHT11's single-wire protocol automatically
   - ``#define`` creates preprocessor macros: ``DHTPIN`` becomes ``2`` and ``DHTTYPE`` becomes ``DHT11`` before compilation
   - ``DHT dht(DHTPIN, DHTTYPE)`` creates the sensor object configured for pin 2 and the DHT11 variant

   .. code-block:: arduino

      #include "DHT.h"

      #define DHTPIN 2
      #define DHTTYPE DHT11

      DHT dht(DHTPIN, DHTTYPE);

#. **Non-Blocking Timer Variables and Sensor Initialization**

   - ``lastReadTime`` stores the millisecond timestamp of the most recent sensor reading
   - ``interval`` defines how long to wait between readings (2000 ms)
   - In ``setup()``, the Serial Monitor starts and ``dht.begin()`` initializes the DHT11 sensor

   .. code-block:: arduino

      unsigned long lastReadTime = 0;
      const unsigned long interval = 2000;

      void setup() {
          Serial.begin(115200);
          dht.begin();
      }

#. **Checking the Clock Instead of Using ``delay()``**

   - ``millis()`` returns the number of milliseconds since the board powered on (up to about 50 days)
   - Instead of ``delay(2000)`` which pauses the entire program, check if 2000 ms have passed since the last reading
   - If yes, update the timestamp and perform the reading; if no, the loop continues immediately — this is the core non-blocking timer pattern

   .. code-block:: arduino

      unsigned long currentMillis = millis();

      if (currentMillis - lastReadTime >= interval) {
          lastReadTime = currentMillis;

#. **Reading the DHT11 and Checking for Errors**

   - ``readHumidity()`` and ``readTemperature()`` return ``float`` values for relative humidity (0–100%) and temperature in degrees Celsius
   - The DHT11 occasionally fails to produce a reading — ``isnan()`` checks if the returned values are valid, preventing your program from printing garbage data

   .. code-block:: arduino

          float humidity = dht.readHumidity();
          float temperature = dht.readTemperature();

          if (isnan(humidity) || isnan(temperature)) {
              Serial.println("Failed to read from DHT11!");
              return;
          }

**Why Non-Blocking Timing Matters**

In the first lesson, you used ``delay(500)`` to blink an LED. During those 500 milliseconds, the board does **nothing else** — no button checks, no sensor readings, no Serial output. The DHT11 requires at least 2 seconds between readings. Compare the two approaches:

.. list-table::
   :header-rows: 1
   :widths: 30 35 35

   * - Feature
     - ``delay(2000)`` (blocking)
     - ``millis()`` (non-blocking)
   * - Program during wait
     - Frozen — nothing runs
     - Continues running — can check buttons, update LEDs, etc.
   * - Responsiveness
     - 2-second lag on every input
     - Instant — loop runs thousands of times per second
   * - Adding another sensor
     - Each sensor adds its own delay, compounding the freeze
     - Each sensor just checks its own timer independently
   * - Battery usage
     - Higher — processor runs at full speed doing nothing
     - Same — but can enter low-power sleep between checks

With ``millis()``, your program can read the DHT11 every 2 seconds **and** simultaneously check a button, blink an LED, update a display, and stream data — all without any of them blocking the others. This is how real embedded systems work.

3. Experiment
----------------

**Adjust the Sampling Interval**

Try changing the ``interval`` value and observe the effect on the data stream:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - ``interval`` Value
     - Effect
   * - ``1000`` (1 second)
     - Faster updates — but DHT11 may not stabilize between readings
   * - ``5000`` (5 seconds)
     - Slower, more stable — ideal for long-term logging
   * - ``100`` (0.1 second)
     - Too fast — DHT11 can't keep up, many "Failed to read" errors
   * - ``60000`` (1 minute)
     - Room climate monitoring — watch temperature change over an hour

The DHT11's minimum sampling period is about 1 second; anything faster and the sensor can't complete a measurement before the next request. The 2-second default is a safe middle ground.


4. Troubleshooting
--------------------

**Serial Monitor shows "Failed to read from DHT11!" repeatedly**

* **Cause:** The DHT11 is wired incorrectly, the library is not installed, or the sensor needs time to stabilize.
* **Solution:** Check VCC → 3.3V, DATA → pin 2, GND → GND. In App Lab, check the **Sketch Libraries** panel to confirm the **DHT sensor library** is installed — App Lab auto-installs libraries declared in the project's ``sketch.yaml``. After power-on, wait a few seconds — the DHT11 needs about 1 second before it can respond reliably.

**Readings are all zeros or negative values**

* **Cause:** The DHT11 module is not receiving power, or the ``DHTTYPE`` is misconfigured.
* **Solution:** Make sure VCC is connected to **3.3V**. Check that ``#define DHTTYPE DHT11`` matches your sensor — using ``DHT22`` with a DHT11 sensor produces invalid readings.

**Humidity reading doesn't change or is stuck at 0%**

* **Cause:** The DHT11's humidity sensing element may be contaminated, or the environment is extremely dry.
* **Solution:** Breathe gently on the sensor — humidity should rise within seconds. If it doesn't change at all, the sensor may be damaged. Some DHT11 clones have very slow humidity response — wait 10–15 seconds after breathing on it before concluding it's broken.

5. Summary
-------------

You've moved beyond simple analog and digital sensors to a device that reports real environmental data. In this lesson, you learned:

* How to install and use an external Arduino library — the DHT sensor library
* How the DHT11 measures temperature (±2°C) and humidity (±5%) and reports them digitally
* How ``millis()`` enables **non-blocking timing** — your program can do multiple things at once without ``delay()`` freezing everything
* How to validate sensor readings with ``isnan()`` and handle failures gracefully
* How to format sensor data for logging — labeled sensor output makes the Serial Monitor a live data readout

The ``millis()`` pattern is one of the most valuable skills in Arduino programming — it transforms your projects from "one thing at a time" to true multitasking.
